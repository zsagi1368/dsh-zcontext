面向 Agent 长会话的分层上下文管理：zcontext 的设计与实测评估

——综合 DSH 原生压缩机制、pi 上下文经济学与 billion-context 预算式策略的系统研究
zDSH 插件研究线 · dsh-zcontext v0.3.0
2026 年 11 月 21 日 · 数据来源：170 轮隔离基准（Phase 2）与 40 轮自发折叠对照（Phase 3）· 全部数字可溯源

摘要（中文）：编码 Agent 的上下文在长会话中持续膨胀，而 API 无状态要求每轮全量重发上下文，导致计费输入随轮次近指数增长。本文在 50 轮隔离基准中实测裸官方路径的计费输入增长 11.8×（前 10 轮均值 109,181 → 后 10 轮均值 1,288,955 token/轮，单轮峰值 3,322,963），定位问题严重性。我们综合三条技术路线——DSH 官方的 surface-replace 折叠通道（compaction-basic 硬底座）、pi 研究线产出的上下文 token 经济学（成本方程 ΣCi×(1−r+r·κ) 与杠杆顺序 C→r→N）、以及 billion-context 的固定水位预算式策略——设计并实现了 zcontext：一个零请求体改写、完全骑乘官方折叠通道的分层上下文管理插件。系统包含观测账本（三态记账）、折叠引擎与 unfold 单节点再物化语义、引导面与压力提醒面、autoFold 服务端自发折叠引擎（三供给、退化链、防反馈环）、发送前预检（估算器+校准台账+按路线挣得的 auto 档）与 SQLite 持久账本。实测回答了三个关键问题：①模型驱动折叠不可依赖——修复接线后模型在 nudge 在场的 20 轮压力臂中自发折叠仍为 0/20；②服务端自发折叠有效——两臂各一次折叠净省 4,576/5,101 token（−88.1%/−88.9%），折叠后次轮计费输入 −44%；③诚实度量是可评估性的前提——三态记账与缓存实测/估计分离使「省了多少」可审计。本文同时给出三条路线的机制对比与水位策略的开放问题。

Abstract (EN): Agent contexts balloon over long sessions while stateless APIs re-send the entire context every turn: in a 50-turn isolated benchmark the vanilla path grows billing input by 11.8× (109,181 → 1,288,955 tokens/turn, peak 3,322,963). Synthesizing three lines of work — the DSH native surface-replace folding channel (compaction-basic as the hard floor), the context-token economics from the pi research line (cost equation ΣCi×(1−r+r·κ), leverage order C→r→N), and billion-context's fixed-water-level budget strategy — we present zcontext, a layered context-management plugin that rewrites zero request bodies and rides the official folding channel exclusively. It comprises an observation ledger (three-state accounting), a fold engine with single-node unfold re-materialization, a guidance/nudge face, a server-initiated autoFold engine (three summary supplies, degradation chain, feedback-loop guard), a preflight window judge with a calibration ledger and per-route earned enforce mode, and a SQLite durable ledger. Measurements answer three questions: (1) model-driven folding is unreliable (0/20 spontaneous folds with nudge present after wiring was fixed); (2) server-initiated folding works (two arms: −88.1% / −88.9% net tokens saved; −44% billed input on the turn after a fold); (3) honest provenance is the prerequisite of evaluability.

1 引言

1.1 问题：增长的上下文在无状态 API 上的计费放大

主流 Agent 框架（Claude Code、Codex、DSH 等）的会话历史均非滑动窗口——API 无状态，每轮必须全量重发上下文[2]。随之而来的计费结构性放大：会话越长，每轮重发的输入越多。我们在隔离环境中对 DSH 官方路径做了 50 轮的量化（§8.1）：前 10 轮均值 109,181 token/轮，后 10 轮均值 1,288,955 token/轮，增长 11.8 倍；单轮峰值 3,322,963 token。由于缓存命中（98.2%）只降低单价、不减计数，「读便宜」并不改变体量增长的事实。

1.2 三条既有路线与本文位置

解决该问题存在三条代表性路线。（a）DSH 原生压缩：compaction-basic 作为硬底座在窗口溢出后由官方压缩链恢复，maxOverflowRetries 限次重试——它是事后恢复，不是事前节流。（b）pi 研究线：从 token 经济学出发，主张「不让垃圾进上下文」的注入纪律，给出成本方程与杠杆顺序（§2.2）——它是离线设计准则，未在 DSH 形态落地。（c）billion-context：以侧车进程维持固定水位（常驻 ~100k）的预算式折叠——它证明了服务端自发折叠的可行性，但其水位策略与窗口大小解耦，且对模型自发采用率的报告（27B 级小模型自发采用为零）与我们的实测一致（§5.1）。

zcontext 的位置：以 pi 的经济学结论为设计准则，以 DSH 官方折叠通道为唯一执行面（零请求体改写），吸收 billion-context「不等模型自觉」的服务端思想并加以机制化（校准驱动、防反馈环、诚实退化）。三者综合的落点是一个插件形态的分层系统，同时兼容「纯插件」与「补丁完全功能」两种部署形态（§7）。

1.3 贡献

本文的贡献有四：①给出长会话计费放大的第一手量化证据（11.8×，§8.1）与模型驱动折叠不可依赖的对照证据（0/20，§5.1）；②提出并实现骑乘官方通道的零改写折叠栈（R1 红线，§3），含单节点 unfold 再物化语义（§4.2）；③设计校准驱动的 auto 预检档——enforce 行为按路线从校准台账「挣得」而非假定（§6）；④两臂实测证明服务端自发折叠的净节省（−88.1%/−88.9%，折叠次轮计费 −44%，§8.2）。

2 背景与相关工作

2.1 DSH 原生上下文管理

DSH（DeepSeek Harness）的上下文由三层机制构成：（i）surface 折叠通道——会话表面（surface）是有序节点序列，官方提供 replace 型原语将 N 个节点替换为 1 个节点，这是官方唯一认可的「收起历史」方式；（ii）compaction-basic——窗口溢出后的恢复链，将上下文交给压缩摘要并在失败时按 maxOverflowRetries 有限重试；（iii）pruner——系统层剪枝。关键约束：任何第三方折叠若想获得官方恢复链的配合（溢出重试、摘要供给），必须经（i）的通道表达；绕过通道改写请求体会破坏缓存前缀与官方不变量（§3）。

2.2 pi 上下文经济学

pi 研究线（2026-08，源码级研究+三轮对抗验证）产出了本设计的经济学基础[3]：

总费用 ≈ Σi Ci × (1 − r + r·κ)，其中 κ ≈ 10

其中 Ci 为第 i 轮平均上下文体量，r 为缓存命中率，κ 为前缀失效放大系数——缓存前缀一字节变化，整条缓存作废，等效成本 ×10。由此导出杠杆顺序 C→r→N 不可反：先压注入纪律与限幅（降 C），再冻结前缀+守护（保 r），最后才考虑摘要（降 N）。该顺序直接塑造了 zcontext 的实施序：观测账本先行（L0 度量），守护与冻结优先于任何折叠动作。

同样来自该研究线的事实：pi 自身哲学是「不让垃圾进上下文」（系统提示 1–2KB、单一扁平历史、工具输出 2000 行/50KB 限幅、晚压缩+迭代式结构化摘要）；Claude Code 与 Codex 均非滑窗——「摘要+保留近期+剪枝工具输出」是行业收敛解。zcontext 的 guidance 面与工具输出限幅思路同源，但把执行面从「改请求」换成「骑官方通道」。

2.3 billion-context

billion-context 是 DSH 生态中的第三方上下文插件（侧车进程形态，独立端口服务）。其策略是固定水位：无论窗口大小，把上下文维持在 ~100k 常驻水位，长期运行、永不遗忘。其公开自述承认在 27B 级小模型上模型自发采用率为零——与我们在 §5.1 的对照数据（0/20）相互印证：模型驱动折叠在当前量级模型上不可依赖，服务端自发折叠是必要路线。zcontext 与其的差异在 §10 对比表：执行通道（官方 surface replace vs 侧车自管）、水位策略（触发线驱动 vs 固定水位）、以及校准驱动的自适应预检。

3 设计原则

四条原则贯穿全部实现，每条都对应一次真实的失败教训或官方约束：

R1零请求体改写。对发往模型的 wire 请求不做任何修改——无 fetch 代理、无 prompt 截断兜底、无请求重写。动机有二：缓存前缀的单调性（A″ 设计：折叠进日志而非改请求，保 prompt-cache 前缀只增不减）；以及官方不变量（request.messages ≡ deriveMessages()）不被第三方破坏。折叠的全部效果通过 surface replace 表达。

R2官方通道唯一性。折叠/展开只经官方 surface replace 原语执行；官方 compaction-basic 永远是硬底座——插件面失效时官方压缩兜底，双保险不互斥。

R3诚实度量。每个数字携带来源标签（measured/estimated/unknown/none），三态记账区分实测、半实测与估计；缓存会计区分 measured 与 estimated；「统计不可用」如实渲染而非伪装成零。可评估性（§8）依赖此原则。

R4fail-soft 全线退化。任何子面故障（账本、估算器、投影器、台账）都退化为「跳过该动作」，绝不阻断请求；每个可选依赖的能力探测 + 显式降级路径（如投影器的 official/local-fallback 双标签）。

4.2 折叠语义与 unfold 的单节点再物化

一次 fold 把连续的表面节点折叠为一个checkpoint 节点（保留摘要与可引用的原始区间索引）；官方 replace 语义要求 N→1。unfold 则将该 checkpoint 再物化为恰好一个多块用户消息，原始内容按日志序内联引用（工具结果带来源注记）——原始轮次不会回到表面的独立消息形态。会话日志永久保留全部原始事件，zctx_recall 可跨折叠检索。这一「线型改变」是骑乘官方通道的诚实代价，在测试中断言而非隐藏。

4.3 工具面、引导面与压力提醒面

模型侧提供 zctx_status（唯一可信账本视图，含缓存会计与校准统计）、zctx_recall 等工具；系统提示注入引导段（fold 判据与规范）；压力提醒（nudge）以 required: true 注册——官方组装器在部分配置下会过滤非必需贡献，required 是其在高压场景存活的机制前提。nudge 仅在阈值跨越后贡献文本，平时零注入（pi 零注入哲学的保守变体）。

5 autoFold：服务端自发折叠引擎

5.1 动机：模型驱动折叠的第一手不可靠性

v0.2 线的设计依赖模型在 nudge 提醒下自发调用 zctx_fold。我们修复接线后做了 20 轮压力臂 + 10 轮正常臂的对照（§8.1 的 B/C 组即其背景）：nudge 文本实测在场（wire prompt 验证），自发折叠仍为 0/20。这与 billion-context 的自述（27B 级小模型自发采用为零）一致。结论：把折叠挂在模型自觉上是不可依赖的——必须把触发权移到服务端。

5.2 触发、选区与供给

autoFold 监听器在服务端每轮评估：估算上下文越过触发线（含 margin）即启动折叠判定。选区由折叠引擎推导（工具对闭合、互斥约束、代数快照校验），不合格即诚实退出（no-qualified-span，零摘要调用）；供给三选一：compaction 官方摘要、external 端点、digest 机械摘要；任一供给失效沿退化链降级而非硬折。防反馈环：折叠事件自身的用量不计入触发估算的往返（避免「折叠→记账→再触发」自激）。

6 Preflight：发送前判定与校准驱动的 auto 档

preflight 是 llm/stream 瀑布的最外层监听器（cordis 语义下最先执行，短路可抑制全部下游成本）：在请求发出前，用官方投影（或标注的本地回退孪生）重投影消息，按 chars/3（对密集 CJK 已知低估）估算体量，判定 estimate > triggerLine × margin（margin 默认 0.9）。

三档语义中，auto 是默认档：enforce 行为（命中即短路——不发请求、零消耗、合成官方协议形态的单终结 chunk）必须从校准台账「挣得」：同 provider+model 最近 8 条可比记录（官方投影、已结算、正计费）中至少 4 条且最差误差 ≤15% 方可升级；冷启动、历史稀疏、估算不准或台账故障一律退化为 observe（只记录不干预）。每次判定写入审计字段 effectiveMode。误报代价被显式声明：一次命中错误消耗一次官方压缩链的 maxOverflowRetries 预算——这就是阈值保守化与「挣得式」设计的动机。one-shot 请求（压缩摘要、会话标题）永不判定，避免压缩链自调自拦。

7 部署形态：纯插件与补丁完全功能

zcontext 支持两种部署形态，运行形态在面板中以补丁标记（patcher marker）实时可见：（a）纯插件模式——仅经官方插件 API 表达（工具/系统提示/命令/llm/tokenMeter/webServer），兼容性最强；（b）补丁完全功能模式——由底座补丁集（多目标单 asar splice、逐文件三态门、marker files 清单）在官方二进制上启用深层面（guard-observe 事件桥等），补丁含自愈计划任务与预适配管线，官方升级落地后自动重打。两形态共用同一插件主体；补丁不可用时自动退回纯插件，面板运行形态行如实显示当前形态（present/absent/unknown）。

9 局限与边界

（1）单纪元覆盖边界。同一单调纪元内（无 compaction/checkpoint 位移），一次提交折叠即把可达 span 压到 minFoldableTokens 地板以下——每纪元一次折叠是实测的诚实上限；跨 checkpoint 吸收仅在窗口恰为 [checkpoint, checkpoint] 时成立。

（2）估算器未标定。chars/3 对密集 CJK 系统性低估；auto 档在台账收敛前行为等价于 observe，故默认路径不会被未标定的估算器硬短路——但绝对精度仍待真机标定（校准台账即为此准备的数据面）。

（3）水位策略未决。当前触发线驱动（快满才折）；billion-context 式固定水位（常驻 ~100k）是 v0.4 候选，涉及预算/预检/autoFold 三面联动，尚未实现。

（4）采用面残余。模型自发采用（文本面/模型面）不在 v0.3 判据内，作为研究候选保留（nudge 措辞强度对照、更强模型对照）。

自适应重试限次——固定auto 档按路线挣得 enforce

11 结论与未来工作

zcontext 证明了：在官方框架提供 surface replace 通道的前提下，零请求体改写的分层上下文管理是可行的，且其经济学基础（杠杆顺序）与执行纪律（诚实度量、fail-soft）可以工程化为 803 项测试守护的实现。实测补齐了该领域少有的第一手数据：官方裸路径 11.8× 放大、模型自发采用 0/20、服务端自发折叠 −88% 级净省与 −44% 次轮计费。未来工作按优先级：①固定水位策略（预算/预检/autoFold 三面联动，v0.4 候选）；②估算器真机标定与阈值修订；③跨 checkpoint 吸收窗口；④模型自发采用的文本面/模型面对照实验。
